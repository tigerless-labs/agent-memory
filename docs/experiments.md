# 实验规范

> 状态 accepted;什么算一个结果、归因需要什么条件、每个 run 必须留下什么。
> 协议与结果在 [experiments/](../experiments/README.md);这里只写规矩。**跑任何实验前先读。**

## 一、四类实验

| 类 | 做什么 | 成本 | 能支持什么结论 |
|---|---|---|---|
| 写侧全跑 | 经历阶段 + 考试阶段,新建 store | 最贵 | W 侧改动;唯一能改变 store 的一类 |
| 读侧重放 | 重放既有 store,只跑考试 | 一次考试/题 | R 侧改动;写侧构造上相同 |
| 离线 | 重判、覆盖率与可检出率探针、参数扫描 | 零宿主调用 | 确定性量,不产生分数 |
| 接入 | 互通、宿主可用性、隔离与自带记忆核验 | 小 | pass/fail,不产生分数 |

**跨类不可并列**:读侧重放的分数与另一次写侧全跑的分数不是同一实验,写侧不同即为不同实验。

## 二、什么才算一个结果

噪声底是量出来的:store 冻结、config 冻结、单一 judge,**同一配置重放两次摆 ±7/120**
(evidence: [p2-optimisation.md](../experiments/results/p2-optimisation.md),P5 两次重放 71 与 57)。因此:

- **n ≥ 120**,分层抽样,全臂同一 episode 列表
- **每臂至少两次重放**。单轮对比不可信,n 再大也不可信
- **逐对 McNemar**,逐个重放两两配对
- **禁止「跨重放取多数」**:两轮臂上它实为并集(任一轮对即算对),同时抬高两臂并偏袒方差大的那一臂
- 差值小于约 7/120 的两行**不可区分**,不得写成排序
- 确定性指标(覆盖率、可检出率、边数、条目数)无随机性,一轮即可,不受本节约束

**负结果照记。**「有功效的负结果」(n 够大、真效应本该显形而未显形)与正结果同等入账;
「没测出来」(n 不足以显形)不是结论,不进 ledger。

## 三、归因:什么时候能说「是这个变量」

- 不变量 9:R 全程固定,分差才能归给 W。守卫按 **recall 指纹 × episode 指纹** 跨臂单值发放。
- **已知盲点:考试模式(fixed / agentic)不在 recall 指纹里。** 凡涉及它的比较必须在
  write-up 里显式声明两臂的考试模式——守卫拦不住它
  (evidence: [p6-list-width.md](../experiments/results/p6-list-width.md) 撤稿)。
- **系统对系统**(不同记忆系统)的比较不适用归因守卫:W 与 R 同时变,结论只能是端到端,
  不能拆成谁写得更好。唯一可分离的是写入覆盖率——它只看落盘了什么。
- **一行是一个配置,不是一个变量。** write-up 必须点名两臂之间所有已知差异。

## 四、每个 run 必须留下

| 必留 | 为什么 |
|---|---|
| config 全量快照 | **recall 指纹不能跨 config schema 反解**:加或移一个 knob 会改变所有指纹,旧运行的配置无法用当前 config 空间搜回来 |
| 考试模式、宿主与模型、judge 设置 | 都不在指纹里 |
| 父 run(重放来源) | 否则「写侧构造上相同」无从核验 |
| 逐题记录 | 结论的可复核性;连同 store 真源一起入 git |

## 五、命名

- run id:`<轮次><变体>`;同一配置的重放加尾号。
- **轮次编号 P<n> 只有一套,按发起顺序递增。** 历史遗留:
  [experiment-harness.md](design/domains/experiment-harness.md) 里的 P1–P3 是原计划三期,
  与结果中的 P1–P9 冲突,以结果为准。

## 六、数据:什么入 git,什么不能删

- 实验数据即证据,**入 git**:逐题记录、题目集、报表、write-up,以及每个 run 的 store 真源
  (记忆文件、archive、config)。不入的只有可重建的缓存(索引、向量、WAL、模型软链——
  不变量 1:索引是真源的投影)、工作目录与进度日志。原始 LongMemEval-S 以 gzip 入库,
  超过 GitHub 单文件上限;用前解压。
- **实验产物只落主工作区,绝不落在 worktree 内。** worktree 是代码的隔离区,不是数据的:
  worktree 路径与 run 产物都被 gitignore,而 `git worktree remove` **不因忽略文件而拒绝**
  (status 为空,不加 force 即删),再叠上「分支落地即删 worktree」的规矩,语料会随分支蒸发。
  在 worktree 里跑实验时,写入路径用绝对路径指回主工作区;harness 对落在 worktree 下的
  写入型路径拒绝启动。
- **冻结语料不可删**:被任何读侧结果锚定的 store 树,它们的真源已在 git 里,但本地缓存删了
  要 `mem rebuild` 才能重放。清单与理由见 [experiments/README.md](../experiments/README.md)。
- benchmark 数据不混入真实用户库;每个 run 独立库;互通测试用专用库。

## 七、失败处理

- **宿主非零退出必须保留 stdout 尾部**:宿主撞额度时把提示打到 stdout 并以 exit 1 退出,
  只留 stderr 会得到空 error(fx1/fx2 两轮 240 次调用因此全废,结论未取得)。
- 额度或限流类失败**停跑**,不把整轮跑成 failed。
- 失败的 run 不进 ledger,并在 write-up 里写明判定为环境性失败。

## 八、判分器是仪器,仪器要标定

benchmark 的 LLM judge 与被测系统同为变量:rubric 写歪会把正确行为判成错误
(实测:弃权题的正确答案是「拒答」,而初版 rubric 写着「拒答判错」)。因此:

- 手工标注用例集 `experiments/judge-calibration.json`(答对/答错/该拒答/不该拒答四类);
  一致率在 rubric 或 judge 模型改动前后必跑。
- judge 单次调用有噪声,取多票多数;当前设置下一致率 ≈ 97%,即每 24 题约 ±1 的判分噪声,
  报表里的差值小于此即为噪声。
- 换 rubric 用存下来的答案离线重判,不重跑宿主。**重判后旧 write-up 的数字即失效,
  必须同步改**——记录与结论不一致时以记录为准。
