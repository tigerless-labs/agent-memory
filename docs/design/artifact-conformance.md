## 第 3 处丢失的代价,已经付过一次

artifact 把「原料层兜底」写成验收指标④,并断言这是全场无人测的空地。设计树没接住这条,
实现里 `archive/sessions/` 因此长期只写不读——原料存在磁盘上,没有任何一条从 query 到它的
路径。P2 的六轮优化撞了三次墙(写入量 3.5× 覆盖率不动)之后才反推出这个机制,补进
`--deep`,再花一轮 n=120 去测。

测出来的结果恰好回答了 artifact 提的那个问题,而且比它设想的更精确:**捞回率是真的**
——gold 答案的可检出率从 20%(仅蒸馏面)升到 37%(加原料面),接近翻倍;
**但端到端得分不动**(53/120 vs 54/120,p=1.000)。按 artifact 的裁决口径「漏针捞回率高
则原料层成立」,原料层成立;它只是不转化为分数,因为瓶颈在下游的回答步。

这一跳的信息损失是真实的,代价是六轮实验。
