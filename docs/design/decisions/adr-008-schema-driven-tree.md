# ADR-008: 树由记忆类型的 schema 在写时生成,目录名不由模型起

**Status**: accepted (2026-09-03);supersedes ADR-005

**Context**: ADR-005 把树交给 M 事后聚簇,写入平铺进四个固定域。实践中 slug 从 abstract 措辞生成,
同一事实换个说法就是新文件,supersede 长期为零;四域与 type 的对照表是代码里的硬编码分类。
OpenViking 证明「类型 schema 决定路径」能让同一实体两次抽取落到同一文件,但它让模型自由填目录名,
同一个人裂成四个目录(其 issue #4043),且一份模板身兼六职。

**Decision**: 记忆类型是数据文件(`schemas/`),只声明类型说明、键字段、分组字段、模式。路径是一条固定约定
`<type>/<group>/<key>.md`,由库从 agent 交回的字段算出。字段来源全局声明:system、menu、field;
**目录段只能来自 system 或 menu**,menu 字段必须匹配对账单给出的现有目录或明确标记新建。
目录没有内容。M 保留搬家、聚簇、合并近义目录、split,作为事后纠正而非建树主路径。

**Consequences**: 好——同键同文件,写时去重免费;分类法是人定的、可 git、可改;agent 的自由度落在
「说什么」而非「库长什么样」;深度与形状可预测。坏——类型之间的边界只靠说明裁定;旧库需要迁移;
出厂类型集是新的设计面。
